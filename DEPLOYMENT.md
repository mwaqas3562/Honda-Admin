# Deploying Honda Admin

Live architecture:

| Piece | Host | What runs there |
| --- | --- | --- |
| Database | Supabase | PostgreSQL, migrations applied by Prisma |
| API | Render (free web service) | Express + Prisma, `apps/api` |
| Web | Vercel | Next.js 16, `apps/web` |

The two services find each other through environment variables, so the order
below matters: deploy the API first, then the web app, then point them at each
other.

---

## 1. Collect the Supabase connection strings

In your Supabase project: **Project Settings → Database → Connection string**.
You need two different URLs, and **neither of them is the "Direct connection"**.

| Variable | Which Supabase URL | Port | Why |
| --- | --- | --- | --- |
| `DATABASE_URL` | **Transaction pooler** | 6543 | Runtime queries. Append `?pgbouncer=true&connection_limit=1`. |
| `DIRECT_URL` | **Session pooler** | 5432 | Prisma migrations and seeding, which need an unpooled session. |

> **Do not use the "Direct connection" URL (`db.<ref>.supabase.co`).** It only
> resolves over IPv6 unless you have bought the IPv4 add-on, and Render's free
> tier has no IPv6 egress — migrations would hang and then fail with
> `Can't reach database server`. The session pooler is the IPv4-safe equivalent.

They look like this:

```
DATABASE_URL=postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=1
DIRECT_URL=postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres
```

If the password contains `@ : / ? # [ ] %`, URL-encode it (`@` → `%40`).

## 2. Push the repository

Render and Vercel both deploy from GitHub:

```bash
git push origin main
```

## 3. Deploy the API on Render

The repo ships a blueprint at [`render.yaml`](render.yaml).

1. Render dashboard → **New → Blueprint** → pick `mwaqas3562/Honda-Admin`.
2. Render reads `render.yaml` and proposes the `honda-admin-api` service. Apply it.
3. It will ask for the values marked `sync: false`. Fill in:
   - `DATABASE_URL` — the pooler URL from step 1
   - `DIRECT_URL` — the session pooler URL from step 1
   - `CORS_ORIGINS` — leave as `http://localhost:3000` for now; step 5 replaces it
4. `JWT_SECRET` is generated by Render automatically. Don't overwrite it with a
   short value: the API refuses to start if it is under 32 characters.

The build runs `npm ci --include-workspace-root --workspace apps/api`, which
installs only the API's 208 packages, then `prisma generate` (via `postinstall`)
and `tsc`. On boot, `start:prod` runs `prisma migrate deploy` to apply all six
migrations to Supabase, then starts the server.

When it goes green, check:

```bash
curl https://honda-admin-api.onrender.com/api/v1/health
# {"status":"ok","service":"api","timestamp":"…"}
```

Note the service URL — the web app needs it next.

### Free tier caveat

Render's free instances sleep after 15 minutes of inactivity. The first request
after a quiet spell takes roughly 30–50 seconds while the container wakes, which
shows up as a slow login. Upgrading to the $7/month Starter plan removes it, as
does any always-on host (Railway, Fly.io).

## 4. Create the admin account

The demo accounts in `prisma/seed.cjs` use the password `password123`, which is
published in this repository — never run it against the live database. Use the
production seed instead, from your machine, with the Supabase URLs in
`apps/api/.env`:

```bash
ADMIN_EMAIL='you@example.com' \
ADMIN_PASSWORD='a-long-unique-password' \
ADMIN_NAME='Your Name' \
npm --workspace apps/api run seed:admin
```

It creates the shop, the four roles, and a single `SUPER_ADMIN`. It refuses
passwords under 12 characters, and warns if demo accounts are already present on
that database. Re-running it resets that admin's password rather than
duplicating the user.

## 5. Deploy the web app on Vercel

1. Vercel → **Add New → Project** → import `mwaqas3562/Honda-Admin`.
2. Set **Root Directory** to `apps/web`. Leave "Include files outside root
   directory" on, so the workspace lockfile at the repo root is used.
3. Framework preset: Next.js (detected). No build command override needed.
4. Add an environment variable, for **all** environments:

   ```
   NEXT_PUBLIC_API_BASE_URL = https://honda-admin-api.onrender.com/api/v1
   ```

   Include the `/api/v1` suffix — every client path is appended directly to it.

   This value is **baked into the JavaScript bundle at build time**, not read at
   runtime. Changing it later requires a redeploy, not just a restart. If it is
   missing, the app silently falls back to `http://localhost:4000/api/v1` and
   every visitor's browser calls their own machine; the bundled code logs a
   `[config]` error to the browser console when it detects this.

5. Deploy, and note the resulting URL (e.g. `https://honda-admin.vercel.app`).

## 6. Point the API back at the web app

In Render → `honda-admin-api` → **Environment**, set:

```
CORS_ORIGINS = https://honda-admin.vercel.app
```

Comma-separate to allow more than one origin (a custom domain, say). No trailing
slash, and no `*` — with `NODE_ENV=production` the API refuses to boot on a
wildcard. Save; Render redeploys automatically.

If you later add a custom domain on Vercel, add it here too, or the browser will
block every API call with a CORS error while the API itself logs nothing unusual.

## 7. Verify the live deployment

1. Open the Vercel URL and log in with the admin account from step 4.
2. Open the browser devtools Network tab and confirm requests go to the
   `onrender.com` host, not `localhost`.
3. Create a customer or a part, reload, and confirm it persists — that proves
   the full path through Render to Supabase works.

## Ongoing operations

**Schema changes.** Create the migration locally against a dev database
(`npm --workspace apps/api run prisma:migrate`), commit the generated folder in
`apps/api/prisma/migrations/`, and push. Render applies it on the next deploy via
`prisma migrate deploy`. Never run `prisma migrate dev` against Supabase — it can
reset the database.

**Backups.** Supabase's free tier keeps daily backups with limited retention.
For real workshop data, turn on Point-in-Time Recovery (a paid add-on) or
schedule your own `pg_dump`.

**Rotating the JWT secret.** Changing `JWT_SECRET` on Render invalidates every
issued token, logging all users out. That is the correct response if a secret
leaks.

**Logs.** Render → service → Logs shows `morgan` output for every request.
The API rate-limits login to 10 attempts per 15 minutes per IP, and general API
traffic to 300 requests per minute.
